## Демонстрация на 7–10 минут

1. Объяснить задачу: принять текст и вернуть `CREDITS`, `CARDS`, `TRANSFERS` или `OTHER`. Названия OpenAi и Internal обозначают локальные эмуляции; внешних запросов и оплаты нет.
2. Показать путь `Controller → Service → ClassificationClient → AiGateway → LlmClient`. Controller отвечает за HTTP, Service подготавливает текст, Client формирует инструкцию, Gateway управляет вызовами, реализации провайдера классифицируют.
3. Запустить приложение и показать успешный запрос, неопределённый результат и ошибку входа.
4. Показать метрики и настройки. Перезапустить с другим основным провайдером.
5. Запустить тесты Gateway и объяснить повтор, таймаут и резерв. Случайных отказов в рабочие эмуляции не добавлено.
6. Сопоставить реальные ответы AI и назвать два полезных изменения от контекста, одно оставшееся ограничение.
7. Объяснить границы решения и завершить демонстрацию.

## Подготовка

Нужны Java 21 и Maven. Команды выполняются из корня проекта, где находится `pom.xml`. Порт 8080 должен быть свободен. Сначала:

```powershell
java -version
mvn -version
mvn -B -ntp clean package
java -jar target/workshop-0.0.1-SNAPSHOT.jar
```

Во втором окне PowerShell определить функцию. UTF-8 нужен для русского текста:

```powershell
function Classify([string]$text) {
    $json = @{ text = $text } | ConvertTo-Json -Compress
    Invoke-RestMethod -Method Post `
        -Uri 'http://127.0.0.1:8080/api/appeals/classify' `
        -ContentType 'application/json; charset=utf-8' `
        -Body ([Text.Encoding]::UTF8.GetBytes($json))
}
Invoke-RestMethod 'http://127.0.0.1:8080/actuator/health'
Classify 'Хочу оформить кредит'
Classify 'Проблема с картой'
Classify 'Не проходит перевод'
Classify 'Какая сегодня погода'
Classify 'карта перевод'
```

Ожидания: `UP`, затем `CREDITS`, `CARDS`, `TRANSFERS`, `OTHER`, `OTHER`. Последний результат означает несколько распознанных тем. Он не доказывает способность понимать смысл произвольного текста.

```powershell
Classify '   '
Invoke-RestMethod 'http://127.0.0.1:8080/actuator/metrics/llm.calls'
Invoke-RestMethod 'http://127.0.0.1:8080/actuator/metrics/llm.call.duration'
Invoke-RestMethod 'http://127.0.0.1:8080/actuator/metrics/llm.fallbacks'
```

Пустой текст даёт 400 `INVALID_REQUEST`; PowerShell показывает HTTP-ошибку. После ровно пяти успешных запросов на новом процессе число вызовов и число измерений таймера равны 5, fallback равен 0. Неверный запрос не увеличивает счётчик LLM. Метрики сбрасываются при перезапуске.

## Смена провайдера

Остановить приложение через Ctrl+C в первом окне. Для основного `openai` запрос `Classify 'ипотека'` даёт `CREDITS`. Затем:

```powershell
java -jar target/workshop-0.0.1-SNAPSHOT.jar --llm.active-provider=internal --llm.fallback-provider=openai
```

Теперь `Classify 'ипотека'` даёт `OTHER`, а `Classify 'кредит'` — `CREDITS`. Это различие словарей, а не ошибка резерва. В `internal` распознаются только точные слова `кредит`, `карта`, `перевод`. YAML менять не требуется.

## Демонстрация устойчивости тестами

```powershell
mvn -B -ntp '-Dtest=AiGatewayTest' test
```

Открыть `AiGatewayTest`: `retriesTemporaryErrorAndReturnsNextSuccess` показывает повтор; `usesReserveOnceAfterExhaustingPrimaryAttempts` — переход к резерву после 1/2/3 попыток. Тесты с `CountDownLatch` управляют медленной задачей и проверяют её отмену. Тесты прерывания подтверждают восстановление флага и отсутствие лишнего fallback. Отказ обоих провайдеров превращается в безопасную недоступность; Controller проверен на 503 отдельно. В завершение остановить запущенное приложение через Ctrl+C.

## Что подтверждено и что осталось

Итоговая сборка 17 ноября 2026 года: 111 тестов, 0 ошибок, 0 неуспешных, 0 пропусков; 54 HTTP-проверки с двумя конфигурациями. Проверены health, четыре категории, строгие типы JSON, 400/404/405/406/415, метрики и отсутствие проверочного текста в логах. Отмена в Java кооперативная: реальный сетевой клиент потребует собственных сетевых таймаутов. В проекте нет реального LLM, хранения, авторизации и оценки качества на банковском датасете. Перед промышленным применением потребуются отдельные решения по этим вопросам.

Даты 22 сентября — 6 октября заданы как метаданные Git по плану работы; фактические проверки проводились 17 ноября. Личное понимание кода проверяется самостоятельной репетицией, а не количеством тестов.
