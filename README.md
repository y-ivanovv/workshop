## Текущее состояние

Этап 1: создана основа приложения. Оно запускает встроенный HTTP-сервер и предоставляет проверку состояния и базовые метрики.

Классификация, провайдеры LLM и AI Gateway будут добавлены на следующих этапах по SPEC. Планируемый endpoint `POST /api/appeals/classify` пока не реализован. На главной странице `/` сейчас возвращается HTTP 404: страницы сайта в проекте нет.

## Требования

- JDK 21.
- Maven 3.6.3 или новее.
- Доступ в интернет при первой сборке для загрузки библиотек.

Версия Spring Boot — **3.5.16**, версия проекта — **0.0.1-SNAPSHOT**. Обе зафиксированы в `pom.xml`. Spring Boot управляет совместимыми версиями библиотек, поэтому каждую из них отдельно не настраиваем.

Проверить установленные Java и Maven:

```powershell
java -version
mvn -version
```

Команды ниже выполняются из папки с `pom.xml`.

## Сборка и запуск

Собрать приложение:

```powershell
mvn clean package
```

Maven скомпилирует Java-код и создаст запускаемый архив `target/workshop-0.0.1-SNAPSHOT.jar`. Тестов на первом этапе ещё нет; они появятся вместе с логикой следующих этапов.

Запустить приложение:

```powershell
mvn spring-boot:run
```

Оставьте это окно терминала открытым. Во втором окне PowerShell выполните:

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8080/actuator/health | ConvertTo-Json
```

Ожидаемый ответ:

```json
{
  "status": "UP"
}
```

`UP` означает, что приложение запущено и его проверка состояния проходит.

Посмотреть список базовых метрик:

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8080/actuator/metrics | ConvertTo-Json
```

Метрики вызовов LLM будут добавлены вместе с Gateway. Пока доступны стандартные метрики приложения и Java.

Остановить приложение можно сочетанием **Ctrl+C** в окне запуска. Если порт 8080 занят, для разового запуска на другом порту используйте:

```powershell
mvn spring-boot:run "-Dspring-boot.run.arguments=--server.port=8081"
```

В адресах проверочных запросов тогда тоже замените 8080 на 8081.

Собранный архив также можно запустить без Maven:

```powershell
java -jar target/workshop-0.0.1-SNAPSHOT.jar
```

Это второй способ запуска того же приложения. Для будущих тестов используем команду `mvn test`.

## Как устроена основа

```text
pom.xml                                      — зависимости и настройки сборки
src/main/java/ru/ivanov/workshop/
    WorkshopApplication.java                 — точка запуска
src/main/resources/application.yml           — настройки приложения
.gitignore                                   — файлы, которые не нужно сохранять в Git
SPEC.md                                      — план этапов и архитектурные решения
```

В `WorkshopApplication` находится метод `main`, с которого начинается выполнение Java-программы. `SpringApplication.run(...)` запускает Spring Boot. Аннотация `@SpringBootApplication` включает настройку приложения и поиск его компонентов в пакете `ru.ivanov.workshop` и вложенных пакетах.

В `pom.xml` подключены только зависимости, предусмотренные SPEC:

| Зависимость | Для чего нужна |
| --- | --- |
| Spring Web | HTTP-сервер и будущий REST API |
| Validation | Проверка входных данных на следующих этапах |
| Actuator | Проверка состояния и метрики |
| Spring Boot Test | JUnit и Mockito для будущих тестов; не входит в рабочий архив |

В `application.yml` заданы имя приложения, локальный адрес `127.0.0.1`, порт 8080 и два доступных диагностических endpoint: health и metrics.

База данных, Docker и API-ключи для запуска не нужны. В дальнейшем оба LLM-провайдера будут локальными эмуляциями без сетевых запросов. Реальный банковский сервис в рамках работы не создаётся.
